# Decisions MSR

Append one bullet per entry, newest last.
- 2026-10-03 (M-01): Matching key is `prop_code + unit_code` (`pairs.unit_key`), cross-checked one-to-one against `unit_id` (`pairs.cross_check_key`). `sSite + sUnitCode` is used only in the collision test/demo.
- 2026-10-03 (M-01): `build_pairs` returns one row per consecutive lease pair, eligible or not; every excluded pair has a non-empty `exclusion_reason` and every eligible pair has an empty one.
- 2026-10-03 (M-01): Pair tests written before the implementation are marked strict `xfail(raises=NotImplementedError)` so `dev` stays green; M-02 removes the marker.
- 2026-10-03 (M-02): Pairs are formed within `pairs.unit_key`, ordered by `lease_start` then `lease_seq`. Segment attributes (`beds`, `is_renewal`, building, province), `sign_date` and `year` come from the later lease of the pair.
- 2026-10-03 (M-02): Exclusion reasons are fixed codes (`missing_rent_or_date`, `non_positive_rent`, `gap_too_short`, `gap_too_long`, `unit_id_mismatch`), joined with `;` when a pair fails several rules. `unit_id_mismatch` = same safe key but a different hUnit on the two leases: the pair is rejected, not guessed.
- 2026-10-03 (M-02): Log growth is computed for every pair with positive rents and a positive gap, eligible or not, so `gap_sensitivity` can re-apply other bounds without rebuilding pairs. Downstream code must filter on `eligible`.
- 2026-10-03 (M-02): Added helpers `exclusion_summary(pairs)` and `gap_sensitivity(pairs, cfg)` (aggregates only) for section 04.
- 2026-10-03 (M-03): `market.registry`: `load_external(path)` and `as_of(external, cutoff)` follow the contract signatures; added `parse_external(raw)` and `validate_external(external, cfg)`. `as_of` gates on `release_date` only (inclusive), never on the reference period. Rows without `release_date` are rejected at load.
- 2026-10-03 (M-03): Allowed `metric` values and provenance tags live in `measure.yaml` `external.metrics` / `external.extracted_by_values`. `rent_cpi` = StatCan rent CPI annual-average % change by province (QC/ON), which is the name FCT's B2 `market_anchor_series` already uses, so FCT needs no change.
- 2026-10-03 (M-03): StatCan 18-10-0004-01 is pulled deterministically from the WDS API (no LLM), tagged `extracted_by=manual` because the contract only allows {manual, llm}. Annual rows are computed from 12 + 12 monthly points, and their release_date is the latest release among those inputs.
- 2026-10-03 (M-03): LLM extraction (claude-opus-5-5, structured output) reads PUBLIC pages only. The page text is passed as data, the prompt forbids values from memory, and answers are cached in `data/public/extraction_cache/` so the step reruns without an API key. Every row lands in `sources_draft.csv` with empty `verified_by`; `promote` copies only human-verified rows into `sources.csv`.
- 2026-10-03 (M-03): CMHC observations are dated to the October survey month and split by `segment` (all / turnover / non_turnover) inside `series_id`.
- 2026-10-03 (M-04): `market.asking.turnover_signal(snapshot, cfg)` returns one row per turnover segment (`prop_code × beds`, `is_renewal=False`) of FCT's frozen weights at the cutoff, so it merges straight onto the weights. Main column: `expected_loggrowth_contract` (annualized log, contractual). Diagnostics: `asking_loggrowth` (before spread), `spread_log`, `n_listings`, `n_spread_leases`, `signal_source` (segment / province_pool / none), `spread_source`.
- 2026-10-03 (M-04): Per listed unit, expected growth = [ln(latest asking in the last `signal_window_months` / contract rent of the latest lease starting before that asking month) + spread] / gap_years, gap from the prior lease start to the asking month. Units with a gap outside the PAIRS bounds are dropped so the signal is comparable with eligible pairs. A lease starting in the asking month is never its own base.
- 2026-10-03 (M-04): Spread = ln(signed contract rent / latest asking posted within `match_lookback_months` up to the signing month), over turnover leases signed in the last `spread_window_years` before the cutoff; per province, falling back to the all-province spread below `min_spread_leases`. Aggregation (median by default) is a config key.
- 2026-10-03 (M-04): The signal is contractual (asking rents are pre-incentive offers). Converting to net is FCT's incentive engine. Units are joined on `pairs.unit_key` (prop_code + unit_code), never sSite.
