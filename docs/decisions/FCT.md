- F-02: `make_snapshot` applies the as-of rules itself (including external `release_date <= cutoff`) instead of calling MSR's `as_of`, which is still a stub; swap in `as_of` once M-03 merges if desired. Units are kept only when every `snapshot_month` is on/before the cutoff month, so historical folds get None without needing config.
- F-02: Headline helpers (`training_pairs`, `winsor_bounds`, `frozen_weights`, `headline_summary`) live in `forecast/baselines.py` because a new shared module would need an INT request; backtest and later engines import them from there.
- F-02: `actual_for_year` winsorizes with bounds learned on pairs known at that year's cutoff, so a year more extreme than all earlier years is capped at the earlier maximum (tested). Weights of segments without pairs are dropped and the rest renormalized; `weight_coverage` is reported.
- F-02: `run_backtest` delegates to `forecast.combine.forecast` (F-05, still NotImplementedError; test is strict xfail). `backtest_baselines` runs B0-B2 through the same fold code and keeps failed baselines as NaN rows with a note.
- F-02: Removed the unused `snapshot` block from `forecast.yaml` (make_snapshot has no cfg argument).
- F-03: Discount share = 1 - rent_net_all_incentives / rent_contract per lease, averaged per cell (lease-level mean, matching the pair-level mean in the headline). Net growth splits exactly: log net = log contract + log(1-d1) - log(1-d0); `net_log_growth` applies it (5% contract + 1 free month = -3.75% net, tested).
- F-03: d1 is per segment (prop_code x beds x is_renewal, so renewals and turnovers are separate) and comes from a straight-line trend over `trend_window_years`, clipped to [0, max_discount_share]. d0 pools renewal and turnover within (prop_code, beds) for the last year, because the previous lease of a future pair can be either type.
- F-03: Thin cells (< `min_leases_per_cell`) fall back to the province pool; `d1_source` shows which segments did. Segments are those of the frozen weights, so the output merges onto them. Config key `min_pairs_per_segment` was renamed `min_leases_per_cell` (it counts leases) and `max_discount_share` added.
- F-04: `build_monthly_index(pairs, cfg, cutoff=None)` keeps the INT stub signature and adds an optional `cutoff` that freezes the segment weights (default: last pair's lease start). Each month is the fixed-weight headline of pairs whose later lease starts in it, winsorized at bounds learned on the given pairs; thin months pool up to `max_pool_months` neighbours per side (overlapping windows, so neighbours are smoothed on purpose).
- F-04: `nowcast(index, cutoff, cfg)` fits a statsmodels local linear trend, projects the last filtered level and slope 12 months with a per-month damping factor (`trend_damping`), and combines the target year's months with calendar-month pair shares from the weight window (leases cluster in some months). Falls back to a trailing mean with a stated reason when history is short or the fit fails; `method` in config can force the fallback.
- F-04: Tests for the index and nowcast live in tests/test_combine.py (an existing FCT test file name); new test file names would need an INT request. F-05 adds the combine tests there.
- F-06: Candidate rule for a concession = same `unit_id`, lease `sign_date` <= concession `date_from` <= `lease_end` (the lease need not have started). One candidate = `unique`; none = `unresolved`/`no_candidate`; several = all joint assignments of the unit's ambiguous concessions are scored by total |reconstructed - reported net rent| and the best kept. A concession is `resolved_by_fit` only if every assignment within `linking.recon_tolerance_dollars` of the best puts it on the same lease, else `unresolved`/`tied_fit`; over `linking.max_combinations` it stays `unresolved`/`too_many_combinations`.
- F-06: Credit arithmetic lives in `reconcile.credit_totals`: lump (PromoPay) credits count once and are never multiplied by `months`; every other code is amount x months. Term = whole months from lease start/end dates (not `term_months_daycount`). `reconstruct_net_rent` keeps the contract signature and gains optional keyword switches (`lump_multiplies_months`, `exclude_codes`) used only by section 05 to show the rejected hypotheses.
- F-06: `recon_error` in LINKS is the absolute error (dollars/month) of the assigned lease after all links; in the reconstruction table it is signed (reconstructed - reported). New config keys `linking.recon_tolerance_dollars` and `linking.max_combinations`.
- F-06: Section 05 is aggregates only (counts, rates, medians); chart uses the shared contract/net colors.
- F-05: `forecast` (model E1_engine_blend) works per frozen-weight segment. Contractual log growth = weighted blend of components that exist, renormalized: renewals = segment history + portfolio nowcast level (F-04); turnovers = segment history + MSR asking-rent signal + nowcast level. Net log growth = contract + log(1-d1) - log(1-d0) from the incentive engine; headline = fixed-weight aggregate (Section 9.1). Headline medians are weighted medians of the segment forecasts (a robustness check, not a median of pairs).
- F-05: History = mean winsorized contractual growth of the segment's pairs in the last `combine.history_window_years` years; thin segments pool by province x renewal flag, then portfolio x renewal flag. Bounds learned on snapshot pairs only. The `combine` weights replaced the F-01 placeholders (`renewal_engine_weight`, `turnover_engine_weight`).
- F-05: No regulatory cap is applied to renewals and no market anchor enters the blend; B2 stays a baseline and TAL/Ontario scenarios are F-07. The nowcast's own net estimate is kept in `components` as a cross-check only (not blended, to avoid counting incentives twice).
- F-05: `backtest_table` / `backtest_all_models` run B0-B2 and E1 through the same folds; `summarize_models` gives MAE on the selection years, the holdout and all years. `run_backtest` uses `forecast`, the same function as `estimate_2026()`.
- F-05: Incentive engine gained a portfolio-level fallback (d1: same renewal flag, d0: all leases) after the 2026 synthetic fold showed a thin province with no usable cell. This is a fix to my own F-03 file, needed for the forecast to run at every fold.
- F-05b (REQUEST-INT-01): `make_snapshot(tables, external, cutoff, external_cutoff=None)` filters external rows on `external_cutoff` (default: `cutoff`, so old calls are unchanged); CRM tables always use `cutoff`. `snapshot_for_year(tables, external, year, cfg, strict=False)` is the one place that applies the agreed rule: CRM cutoff Dec 31 of year-1, public data Jan 31 of `year`; `strict=True` is the Dec-31 sensitivity. Backtest folds and any 2026 forecast must build their snapshots through it.
- F-05b: `run_backtest` reports the strict version in `coverage["sensitivity_strict_dec31"]` when `forecast_years.external_cutoff_strict_sensitivity` is true (BacktestResult fields are unchanged). `backtest_table` / `backtest_all_models` take `strict` and add a `rule` column ("jan31" / "dec31_strict") plus forecast/actual contract columns; `backtest_both_rules` returns both; `summarize_models` summarizes per rule.
